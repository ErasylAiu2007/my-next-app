# 🎬 Creator Portfolio — Техническое задание

## 1. Описание проекта

**Название проекта:** Creator Portfolio

**Тип проекта:** Персональный сайт-портфолио с системой управления контентом.

**Технологии:** Next.js, React, TypeScript, Tailwind CSS.

### Цель проекта

Создать современный сайт-портфолио для видеографа и создателя контента. Сайт позволит посетителям просматривать видеоролики, фотографии, услуги и цены, а также связываться с автором для заказа съёмки.

В системе предусмотрены три роли: **пользователь, модератор и администратор**. Каждая роль имеет определённые права доступа и возможности.

## 2. Основные задачи проекта

- Создание современного и удобного сайта-портфолио.
- Размещение фотографий и видеороликов.
- Отображение услуг и стоимости съёмки.
- Регистрация и авторизация пользователей.
- Разграничение прав доступа в зависимости от роли.
- Создание панели модерации контента.
- Создание административной панели управления сайтом.
- Обеспечение безопасности пользовательских данных.

## 3. Роли пользователей и их возможности

### 3.1. Пользователь

Пользователь — обычный посетитель сайта, который может зарегистрироваться и использовать основные функции платформы.

**Возможности:**
- Просматривать главную страницу и информацию об авторе.
- Смотреть опубликованные фотографии и видеоролики.
- Ознакомляться с услугами и ценами.
- Искать работы по категориям.
- Отправлять заявки на съёмку.
- Регистрироваться и входить в личный кабинет.
- Редактировать собственный профиль.
- Отправлять отзывы и комментарии, если эта функция реализована.

**Ограничения:**
- Не может управлять чужими материалами.
- Не имеет доступа к панели модератора.
- Не может изменять роли других пользователей.
- Не может изменять настройки сайта.

### 3.2. Модератор

Модератор отвечает за проверку материалов и соблюдение правил сайта.

**Возможности:**
- Входить в панель модерации.
- Просматривать материалы, отправленные на проверку.
- Одобрять или отклонять публикации.
- Проверять комментарии и отзывы.
- Скрывать спам и материалы, нарушающие правила.
- Рассматривать жалобы пользователей.
- Просматривать историю собственных действий по модерации.

**Ограничения:**
- Не может назначать администраторов.
- Не может изменять системные настройки.
- Не может самостоятельно повышать свои права доступа.
- Не имеет полного доступа к управлению аккаунтами.

### 3.3. Администратор

Администратор отвечает за полное управление сайтом и его пользователями.

**Возможности:**
- Получать доступ к административной панели.
- Создавать, редактировать и удалять проекты.
- Публиковать и скрывать материалы.
- Управлять пользователями и модераторами.
- Назначать и изменять роли пользователей.
- Управлять категориями, услугами и ценами.
- Просматривать жалобы и результаты модерации.
- Изменять настройки сайта.
- Просматривать журнал действий пользователей и сотрудников.
- Контролировать работу основных функций платформы.

## 4. Функциональные требования

### 4.1. Регистрация и авторизация

- Регистрация новых пользователей.
- Вход в личный кабинет.
- Безопасное хранение паролей.
- Управление пользовательскими сессиями.
- Проверка прав доступа в зависимости от роли.
- Защита страниц и серверных функций от несанкционированного доступа.

### 4.2. Главная страница

- Отображение имени и информации об авторе.
- Представление основных услуг.
- Демонстрация лучших работ.
- Удобная навигация по сайту.
- Кнопки перехода к портфолио и контактам.

### 4.3. Портфолио

- Отображение фотографий и видеороликов.
- Разделение работ по категориям.
- Просмотр отдельных проектов.
- Добавление описания к каждой работе.
- Публикация только одобренных материалов.
- Управление проектами пользователями с соответствующими правами.

### 4.4. Система модерации

- Отображение списка материалов, ожидающих проверки.
- Одобрение или отклонение публикаций.
- Добавление причины отклонения.
- Рассмотрение жалоб пользователей.
- Сохранение истории решений модераторов.

Для материалов предусматриваются следующие статусы:
- **Черновик** — материал ещё не отправлен на проверку.
- **На проверке** — материал ожидает решения модератора.
- **Опубликован** — материал доступен посетителям сайта.
- **Отклонён** — материал не прошёл проверку.

### 4.5. Панель администратора

- Просмотр общей статистики сайта.
- Управление аккаунтами пользователей.
- Назначение ролей.
- Управление портфолио и категориями.
- Управление услугами и ценами.
- Контроль работы модераторов.
- Просмотр журнала действий.
- Настройка параметров сайта.

### 4.6. Система обратной связи

- Отображение контактной информации.
- Ссылки на Instagram и WhatsApp.
- Форма отправки заявки на съёмку.
- Сохранение заявок для дальнейшей обработки.
- Возможность просмотра заявок уполномоченными сотрудниками.

## 5. Матрица прав доступа

| Функция | Пользователь | Модератор | Администратор |
|---|---|---|---|
| Просмотр опубликованных работ | Да | Да | Да |
| Редактирование своего профиля | Да | Да | Да |
| Отправка материала на проверку | Да | Да | Да |
| Проверка материалов | Нет | Да | Да |
| Одобрение публикаций | Нет | Да | Да |
| Управление всеми проектами | Нет | Ограниченно | Да |
| Управление пользователями | Нет | Нет | Да |
| Назначение ролей | Нет | Нет | Да |
| Изменение настроек сайта | Нет | Нет | Да |
| Просмотр журнала действий | Нет | Ограниченно | Да |

## 6. Нефункциональные требования

- Адаптация сайта под компьютеры, планшеты и смартфоны.
- Быстрая загрузка страниц.
- Удобный и понятный интерфейс.
- Оптимизация изображений и видеоматериалов.
- Проверка вводимых пользователями данных.
- Безопасное хранение информации.
- Защита от несанкционированного изменения ролей.
- Читаемый и поддерживаемый программный код.

## 7. Используемые технологии

- **Next.js** — создание страниц и серверной логики приложения.
- **React** — создание пользовательского интерфейса.
- **TypeScript** — разработка с проверкой типов данных.
- **Tailwind CSS** — оформление страниц и адаптивный дизайн.
- **PostgreSQL** — хранение пользователей, проектов и заявок.
- **Git** — контроль версий проекта.
- **GitHub** — хранение исходного кода и совместная работа.

- `app/globals.css` — глобальные стили.
- `portfolio/` — страницы портфолио.
- `services/` — страницы услуг.
- `dashboard/user/` — раздел личного кабинета пользователя.
- `dashboard/moderator/` — раздел модерации.
- `dashboard/admin/` — административный раздел.
- `api/` — серверные обработчики запросов.
- `components/` — повторно используемые компоненты интерфейса.
- `lib/` — вспомогательные функции и настройки.
- `public/` — изображения, иконки и другие статические файлы.
- `types/` — определения типов TypeScript.
- `package.json` — зависимости и команды запуска.
- `README.md` — документация проекта.

## 9. Безопасность

- Пароли хранятся только в виде криптографических хешей.
- Права доступа проверяются на сервере.
- Пользователь не может получить дополнительные права через изменение данных в браузере.
- Административные маршруты защищены авторизацией.
- Важные административные действия записываются в журнал.
- Доступ к персональным данным предоставляется только уполномоченным лицам.

В результате разработки должен быть создан современный адаптивный сайт-портфолио с регистрацией пользователей, разграничением прав доступа, системой модерации и административной панелью.

Посетители смогут просматривать работы и отправлять заявки, модераторы — проверять материалы, а администратор — управлять пользователями, контентом и настройками сайта.
